## 已确认

- 产品目标是帮助学习者实际使用英语交流，当前重点为口语和听力；首个练习采用“先听后用”。
- 先探索用户本人的学习需求，暂不确定更广的目标人群。这不等同于决定产品永远只供个人使用。
- 新版本允许放弃旧数据，重新构造领域模型，见 [ADR 0001](adr/0001-rebuild-domain-without-legacy-data-compatibility.md)。
- 架构重设计的动机是改善可维护性与代码质量；长期由用户本人维护。
- 已选择 Next.js、Drizzle、Neon 与 Better Auth；Vercel 为首选部署平台，实际语音与跨地区访问仍需部署验证，见 [ADR 0004](adr/0004-next-drizzle-neon-better-auth.md)。
- 用户明确希望退出 Supabase，音频存储替代方案暂缓讨论。退出方向已定，完成退出仍须移除实际代码依赖。
- 用户描述的具体困难包括：想表达一句话却不知道怎样说，以及说话时卡词、不知道如何组织句子。尚未确认这些困难主要来自陌生表达、已知表达提取、句子组织或其他原因。
- 首版必须包含登录和注册，先通过测试名单限制注册，供用户本人和少量测试者使用；公开注册留待学习流程、服务和费用验证后决定。
- 首版采用邮箱密码注册登录，包含邮箱验证、忘记密码与密码重置，暂不加入第三方登录；邮件投递服务尚未确定。
- 使用范围需要同时覆盖中国大陆与海外。实际访问和语音链路须按两类地区验证，不能仅依据平台支持 Next.js 推断体验。
- 用户强调口语与听力相辅相成，希望重视听觉输入对表达的作用，并选择先接触材料、再尝试运用的顺序；听说时间比例尚未具体分配。
- 用户接受首版由网站提供少量经过检查的短对话；不把用户导入材料或按话题即时生成材料作为首版起点。
- 听完后的任务是表达用户自己的情况，例如听他人谈周末计划后，说自己的计划；首个流程不以复述材料或角色对话为主要输出形式。
- 一次完整练习按约 5–10 分钟设计，包含听、理解、开口及再次尝试。这是体验与范围目标，不是学习效果保证，也不是强制结束练习的时限。
- 首次播放默认隐藏原文，用户随时可以重听、查看原文和中文释义。表达时先提供关键词或句式提示，主动求助后可查看完整示例。
- 用户录完一段后接收反馈，优先评价意思是否清楚，最多指出两个最影响理解的问题，允许重录；不边说边打断纠错。用户进一步确认允许零个纠错项，表达清楚时如实说明，可选替代表达不当作错误。
- 首版不提供综合分数，也不以语法完全正确作为练习完成条件。完成练习不等同于掌握表达。
- 首版保留登录注册、材料选择、听说练习、反馈和练习记录；旧写作、独立 AI Coach、自由口语对话不进入新版首发范围，见 [ADR 0003](adr/0003-focus-first-release-on-listen-then-use.md)。
- 支持从材料页或历史记录手动重练，保留各次作答与反馈以供对照；暂不做自动复习日程、连续打卡或“已掌握”判定。这并未确定原始录音的存储方案或保留期限。
- 保持单个 Next.js 应用，按业务组织模块，不预先拆分多套应用或后端；必要的分离由实际部署验证决定。
- 首批材料从日常交流起步，覆盖介绍自己、描述一天、周末计划、表达喜好、邀请与拒绝、解释原因；先做少量短对话，每篇对应表达自身情况的任务，难度通过用户试用调整。
- 首版流程为录音、转写、查看并纠正识别错误、获得表达反馈。用户改正识别结果是为了还原原话，改善表达应重新作答。
- 首版反馈以转写文字为依据，聚焦措辞和句子表达，不评价发音、语调或停顿，界面需明确这一能力边界。
- 按用户最新决定，首版仅提供中文界面，适配手机和电脑浏览器，暂不做原生 App；取消此前的双语切换要求。
- 操作文案、练习说明和 AI 反馈说明统一使用中文，英语学习材料、示例表达和用户的英语作答保持英文；不设置界面语言偏好或切换入口。
- 首批材料随项目维护，文本、音频与任务一起检查后发布；首版不做内容管理后台，更新时保留旧练习引用的内容版本。
- 从历史重练使用原内容版本，从材料目录开始使用最新版；旧版撤下后保留历史，但不能用旧版重练，应明确提示可另选新版，不自动替换。
- 获得有效反馈后，用户可选择再次作答或结束练习。历史记录支持重练和删除整次练习及其作答、反馈；删除失败不得显示为成功。录音保留和删除规则随存储方案确定。
- 已结束练习不再追加作答；手动重练创建新练习，原练习及其作答、反馈保留。未结束时重新表达属于同一练习中的再次作答。
- 只听材料或尚未获得反馈时离开，练习保留为未结束，可继续或删除；关闭网页不算完成。主动提交并被系统接收后才形成正式作答，未提交录音不进入历史，离开可能丢失，应明确提示。
- 未结束练习允许更正确认文本；旧反馈保留并注明对应旧文本，新文本需重新请求反馈。已结束练习只读，仍可整次删除或重练。
- 至少一次作答有当前有效反馈、且没有正在处理的请求时可以结束；其他作答可保留失败或尚未核对的状态，不要求最后一次也成功。
- 具体识别、反馈、邮件与文件服务及其费用留到真实接入前比较决定；开发先用明确标识的测试替身验证业务，不把替身跑通作为首版可用的证明。

## 已确认的架构方向

已确定以一个 Next.js 应用和按业务组织的 Module 为起点。`identity` 负责身份与账号访问资格，`learning-content` 负责发布版本和内容可用性，`practice` 负责记录所有权与完整学习过程。页面、Server Actions 和 Route Handlers 使用公开 Interface；作答、转写、反馈和历史暂不拆成独立业务 Module。表与查询归所属 Module，依赖集中装配，外部 Adapter 不直接写练习状态。持久化内容版本、确认文本版本、反馈依据和技术处理记录各自表达明确含义。具体字段、并发控制方式与部署恢复执行路径在实施时验证，不以目录层数或抽象数量作为质量指标。

验收应优先覆盖真实行为，例如用户只能操作自己的记录、重复提交不会重复产生业务副作用、语音服务失败后状态可解释且可恢复。具体业务行为须随首条学习流程确定，不能机械继承旧功能或旧错误。

## 已选练习顺序与待验证的学习假设

用户提出“能说出来的前提是听过很多”。这反映其对输入的重视，不在文档中将其记为所有学习者、所有表达均成立的必要条件。Nation 的四条线框架同时强调意义输入、意义输出、语言知识学习与流利度发展，可为兼顾输入和输出提供设计参考；该框架不构成本项目某种练习流程有效的实验证明。来源：[Nation (2007), The four strands](https://openaccess.wgtn.ac.nz/articles/journal_contribution/The_four_strands/12552167)。

用户已选择“先听后用”，而不是把先尝试表达、卡住后补听示范作为首个练习的起点。这一选择不排除练习中按需回听或求助，也不排除以后加入其他形式。

已确定的流程骨架：听网站提供的短对话，按需查看原文与释义，再借助其中的表达说出自己的情况；录完后查看并纠正转写，确认后获得少量重点反馈并可再次尝试。一次约 5–10 分钟，之后可手动重练并对照历次作答。尚未验证学习效果。
