# #12 再次作答与对照实施记录

日期：2026-10-11。实施基线：`95fc042`；范围为 #12 的 P07、A04 与 U01。

## 行为与实现

详情页增加“再次作答”入口，点击后将焦点和视口带回录音区，复用原来的录音、试听、提交、识别、确认及反馈流程。草稿未处理完、接收结果待核对、尚未初始化或录音服务不可用时，该入口不可用；已结束练习不显示入口。

各次作答以独立的具名区域和编号呈现，说明再次作答与识别/反馈重试的区别，可逐次对照原始转写、确认文本及对应反馈。再次作答不会清空前一作答的界面或持久记录。新的录音沿用既有 `crypto.randomUUID()` 草稿提交标识；结果不确定仍按原标识核对，不生成重复作答。

不增加业务操作、数据迁移或平行状态来源。既有提交唯一约束、公开接口的归属检查、练习事务锁和按作答保存的转写/反馈已能承载本票，新增专项测试验证这些行为。练习状态来自练习本身，不从最后一次作答推断。

## 测试边界与红绿证据

采用首版规格 Testing Decisions 已确认 seam：practice 公开接口、真实隔离 PostgreSQL、外部识别/反馈 Adapter 替身，以及真实登录会话的浏览器流程。数据库写入仅用于创建测试身份 fixture；业务结果通过公开接口观察。

先写浏览器验收：第一份有效反馈出现后点击“再次作答”。原实现实际超时失败，定位为找不到该按钮；随后补充最小界面入口和具名作答区域，两种视口通过。既有后端行为的专项测试无需修改业务实现即可通过，不将其宣称为新增服务端红绿实现。

浏览器初次绿色验证时，移动场景在重试反馈尚在处理中就读取结果，失败值为 `processing`；测试改为通过公开接口等待该次重试到达 `failed` 后断言。最终两视口通过。测试 fixture 初稿漏传时钟，修正为真实时间后通过，该错误不属于产品缺陷。

公开接口专项覆盖：

- 同一练习同时拥有成功反馈、识别失败、识别完成待核对及识别处理中四次作答；第一份成功作答逐字段保持不变。
- 外部识别 Adapter 的栅栏控制处理顺序，真实数据库执行登记及写回；再次识别保留原作答 ID/提交标识，不增加次数。
- 再次作答的相同标识并发提交只产生一份接收结果；另一录音复用该标识返回冲突。
- 跨账号读取、查询提交、保存录音、提交、识别、确认及请求反馈均被拒绝；原记录保持不变。

浏览器通过真实 MediaRecorder（Chromium 显式假麦克风）录制和试听两次，第二次录音提交之前只有原作答；提交后两次作答 ID 和提交标识不同。第二次反馈失败及重试不覆盖第一次文本与有效反馈；刷新后仍保持原练习与两次记录。页面无横向溢出。
