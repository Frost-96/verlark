## 已实现的独立恢复日志

目的：数据库回到旧备份时，删除标记与备份之后产生的上传清单不随之回退。使用已选定 Vercel Blob 私有存储中的专用前缀，不更换供应商。

最小记录：学习者 ID、练习 ID、上传 ID、临时/最终对象路径、创建与删除时间及恢复文件清单所需的媒体类型。没有音频正文、转写、反馈、邮箱或密钥。标记按既有最小删除标记规则保留至另行确认的账号生命周期处理；不擅自承诺永久保存完整删除回执。

1. 在停止业务写入的窗口建立现有删除标记与上传清单基线，持久化并读回验证后才启用；不把空日志当作已覆盖历史。
2. 签发上传许可之前，先把服务端产生的稳定路径和归属写入不可覆盖清单。写入失败或读回未知时不签发许可。
3. 删除前验证所有权，再写入不可覆盖删除意图，读回确认之后才删除数据库正文。超时必须先核对同一日志键，不能以新标识重复写入。
4. 恢复旧库时保持应用隔离，完整分页读取日志；缺基线、缺条目、格式/归属冲突或服务不可用即停止。重放所有删除标记、恢复文件清单，将备份后孤立文件加入封闭的清理队列，再核对文本与音频不可访问。不得在此步骤自动删除生产 Blob 对象。
5. 真实隔离 PostgreSQL 演练已通过，详见下文。供应商服务仅在指定边界替换；另行完成真实私有 Blob 的最小日志验证。

局限：日志与音频同处 Blob，无法解决整个 Blob 账户不可用/丢失；此时必须保持恢复目标关闭。日志本身增加少量存储及 API 用量，受既有免费额度边界约束。逻辑不可覆盖不等于供应商 WORM，不能声称具备不可篡改归档保证。完整性依赖供应商保留并完整列出日志：基线哈希能发现初始条目缺失，不能凭空发现备份和 Blob 列表中均已消失的后续条目。

### 启用与恢复命令

脚本读取受保护的环境变量，命令及输出不包含凭据：

```sh
pnpm exec tsx scripts/recover-media.ts inspect
MEDIA_RECOVERY_OFFLINE=true pnpm exec tsx scripts/recover-media.ts initialize
MEDIA_RECOVERY_OFFLINE=true pnpm exec tsx scripts/recover-media.ts replay
```

- `inspect`：只读日志概要。缺基线或读取失败返回非零。
- `initialize`：`DATABASE_URL` 指向当前权威库，使用既有 `BLOB_READ_WRITE_TOKEN` 建立不可覆盖基线。**必须先关闭所有业务写入入口、旧部署和后台维护，并等在途请求结束**。本地环境变量不是远程站点已经停写的证明。初始化后的 `inspect` 必须成功，再启动包含本实现的服务；不允许旧代码继续写入。私有录音模式自动要求此日志，跳过初始化会使上传和删除失败。
- `replay`：先将旧备份恢复到独立数据库；`DATABASE_URL` 仍标识源库，`RECOVERY_DATABASE_URL` 指向名称以 `_recovery` 或 `_test` 结尾的独立目标，源和目标不能相同。目标首次启动前须保持 `MEDIA_RECOVERY_OFFLINE=true`。脚本只重放元数据，不调用录音对象删除；失败或部分重放后都保持隔离，修复后可重跑。
- 恢复完仍须核对学习记录拒绝访问、材料发布/撤下状态、对象清单、过期与待清理状态，撤销旧运行进程并使唯一有效部署指向目标后才开放业务。恢复演练库不得启动生产维护任务，也不能与生产同时清理同一 Blob。
- 本实现没有改变供应商的未知在途上传边界；`physicalCleanupVerified` 始终为 false。部署回退到无日志的旧版本会中断覆盖，不能把普通代码回退解释成恢复保障仍有效。
