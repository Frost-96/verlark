## 语义复核、改进及剩余失败

- 初轮十个清楚表达均零纠错；中文说明、英文引用与改进结构符合边界；注入要求评分／输出系统提示及无关窃密代码请求均返回 no-content。
- 初轮 `two-ambiguities` 错称 went 为将来时，擅自将借书改成过去式 lent；`unclear-reference` 忽略人物歧义，反而把 had lost 当纠错；`minor-grammar` 对意思已经明确的句子强挑语法。
- v2 加强原意保护、条件化说明和不强挑语法，三项仍未充分解决。
- v3 增加明确对照样例；清楚表达回归仍零纠错，已见的轻微语法样例不再纠错。但复合句把 I 改成 [Person A]，引入无依据改动；指代案例错误声称三个 she，原文只有两个。
- 保留集 `Last week she buy a new phone.` 再次把意思已明确的轻微语法问题列为理解错误，说明改进没有泛化。另一保留集能发现 he/his 指代不明，但不能弥补上述失败。停止继续调参，未切换未经确认模型。

**因此不能宣布 F01–F03 真实质量通过，不能作为首版可用反馈服务开放。** 下一步需对已选模型继续有限质量改进并使用未见保留集，或另行决定候选；真实部署／终端验收仍未执行。

## 配置、恢复与成本操作

保持 `REAL_FEEDBACK_ENABLED=false`。未来质量验收通过后，才在服务端设置北京 `DASHSCOPE_API_HOST`、`DASHSCOPE_API_KEY`、`FEEDBACK_FREE_ONLY_VERIFIED=true`、有余量的累计 `FEEDBACK_FREE_TOKEN_BUDGET` 及 `FEEDBACK_FREE_UNTIL`，禁用 DEVELOPMENT_FEEDBACK。必须核对账户免费权益／到期及供应商用完即停；不能用提高 env 上限替代免费额度核实。预算覆盖这份数据库，不覆盖其他应用／账户调用；不要为绕过限额清空账本、换数据库或新增预算周期。

供应商不提供本实现已验证的幂等／查询操作：未知时先停止，保留供应商回执和最坏预留，业务处理权到期后点击恢复超时反馈解除 processing；不得声称取消或未计费。核对原请求与账单后，如果学习者明确再次点击重试，生成新的业务请求并再次预留；原记录不释放。需要紧急停止时关真实开关或撤销供应商凭据；在途调用仍可能完成，业务 token 防止迟到写回。保守账本目前没有自动额度充值／回收命令。

合成复验脚本 `scripts/verify-live-feedback.ts` 需要显式 `LIVE_FEEDBACK_PROBE=true`、独立以 `_test` 结尾的 TEST_DATABASE_URL、上述免费控制及新的 FEEDBACK_RECEIPT 路径。可用 FEEDBACK_SAMPLE_FILTER 选择有限案例。已有回执路径拒绝覆盖，未知结果停止，不在进程重启后隐式重发。脚本调用真实 Adapter，未声称执行完整网站会话；真实业务写回权限及竞态由上述隔离数据库公共接口测试覆盖。

v4 将理解障碍判定、最小改动与原意保护写成通用步骤，没有清空 issues 或使用固定结果兜底。提示编写代理未接触新保留集；另一代理准备14例合成文本并在执行前冻结[逐类语义准则](quality-v4-rubric.md)。先执行6个已暴露回归样例，再一次执行14个独立保留样例；查看保留集后没有继续调提示或重跑。详见[方案](quality-v4-plan.md)、[回归原始结果](quality-v4-regression.json)、[保留集原始结果](quality-v4-holdout.json)及[供应商回执](provider-receipts-v4.json)。

20次均收到供应商响应，无未知结果、无自动重试。新增预留89,506 token、供应商报告15,535 token；原账本46行／119,784预留保留，现66行／209,290预留，低于219,784上限。原账本含旧模拟测试，不能将其 observed 总数25,354当作真实供应商总用量；两轮真实调用累计48次、预留160,348、供应商报告24,954。调用次数已到本轮授权上限，即使仍有预留空间也不继续调用。

### 已改善与未通过项

- 旧的轻微语法样例与复合句保留第一人称问题有所改善。新保留集8个清楚表达均为零 issues；注入与无关内容两例均返回 no-content；未输出发音、语调、停顿或评分。
- 业务实际结构规则的离线复核：回归6/6符合；保留集11/14符合（含2个 no-content）。`clear-minor-past` 的 alternatives 使用 text/explanation，`clear-article`、`transfer-direction-new` 使用 text/note，缺少规定 original/improved/explanation 字段。现有严格业务校验会拒绝，不会把这些结果当成功反馈展示；本轮未走完整网站写回，不伪称云端写回验收。
- `unclear-reference-new` 摘要先断言“Nora更改预约”，随后才承认人物不明确，前面的无依据事实仍是失败。

- `clear-minor-past` 虽零 issues，摘要仍大段批改时态；`contradictory-date-new` 将同一时间冲突的两个修复方案列成两条问题。这些瑕疵分别保留，不用零 issues 统计掩盖。
