## Problem Statement

学习者希望使用英语交流，当前遇到的困难是想表达却不知道怎么说、开口时卡词、难以组织句子。首版先服务用户本人及测试名单中的少量学习者，同时关注听力理解与口头表达。困难的具体成因尚未验证，不据此预设英语等级或学习诊断。

学习者需要从可理解的短对话中接触表达，再尝试说出自己的情况，得到少量可行动的反馈，并保留再次尝试的记录。网站需要清楚区分识别错误与表达问题、一次作答与整次练习、处理失败与学习结果，避免让学习者误以为提交成功、结束练习或获得反馈就代表掌握表达。

维护者需要围绕这条完整流程建立可维护的单应用结构。旧数据与旧功能不构成兼容要求；已确认的新模型和业务边界指导重建。

## Solution

提供中文界面的“先听后用”网站，支持手机和电脑浏览器。学习者完成邮箱认证后，选择经过检查的日常英语短对话，先聆听，再按需查看材料原文、中文释义和表达提示，围绕配套任务表达自身情况。录音可试听、丢弃和重录；主动提交被系统接收后才形成正式作答。

系统识别作答，学习者核对并纠正识别错误，确认文本后请求表达反馈。反馈说明使用中文，英语原话和改进表达保持英文；依据确认文本判断意思是否清楚，指出零至两个最影响理解的问题，不评价发音、语调或停顿。学习者可在同一练习中再次作答，或满足条件后主动结束。历史支持查看、继续未结束练习、重练及删除整次练习。

一次完整练习按约 5–10 分钟设计，这是体验目标，不是自动结束的时限或学习效果保证。首批主题覆盖介绍自己、描述一天、周末计划、表达喜好、邀请与拒绝、解释原因；材料数量、难度与制作方式在内容检查和试用时落实。

## User Stories

以下按“作为某角色，我希望某项能力，以便获得某种收益”列出首版故事；故事编号用于关联验收，不表示实现状态或优先级。

1. 作为测试名单中的学习者，我希望用邮箱和密码注册，以便建立自己的学习记录。
2. 作为学习者，我希望完成邮箱验证后进入受保护流程，以便使用经过确认的账号学习。
3. 作为学习者，我希望登录、退出，并在会话撤销后失去原会话访问能力，以便控制账号访问。
4. 作为忘记密码的学习者，我希望通过邮件恢复密码，以便重新使用账号。
5. 作为学习者，我希望只有自己能读取或变更自己的练习、作答与反馈，以便保留私人学习经历。
6. 作为维护者，我希望首版按测试名单限制注册，以便先与少量测试者验证流程和服务。
7. 作为学习者，我希望在手机和电脑浏览器中使用中文操作、说明和错误提示，以便顺畅完成学习。
8. 作为学习者，我希望从经过检查的日常短对话中选择材料，以便练习常见交流情境。
9. 作为学习者，我希望首次播放默认隐藏材料原文，并可随时重听，以便先尝试听懂内容。
10. 作为学习者，我希望按需查看材料原文和中文释义，以便核对和理解所听内容。
11. 作为学习者，我希望材料配有表达自身情况的任务，以便把听过的表达用于自己的意思。
12. 作为学习者，我希望先看到关键词或句式提示，并在主动求助后查看完整示例，以便按需要获得帮助。
13. 作为学习者，我希望录音后试听、丢弃或重录，以便选择实际提交的表达。
14. 作为学习者，我希望知道未提交录音可能随离开丢失，以便决定先提交还是丢弃。
15. 作为学习者，我希望系统明确告知作答是否已接收，以便理解它是否进入历史。
16. 作为学习者，我希望在提交响应丢失后核对原提交结果，以便避免重复记录同一次表达。
17. 作为学习者，我希望识别失败时仍保留已接收的作答，并可重新识别，以便继续处理原录音。
18. 作为学习者，我希望区分材料原文、识别转写和确认文本，以便知道每段文字的来源与用途。
19. 作为学习者，我希望纠正转写中的识别错误后再确认，以便反馈依据还原我实际说过的话。
20. 作为学习者，我希望在未结束练习中再次纠正识别错误，以便修正遗漏的识别问题。
21. 作为学习者，我希望更正后保留旧文本对应的反馈，并为新文本重新请求反馈，以便理解不同反馈的依据。
22. 作为学习者，我希望录完并确认文本后再获得反馈，以便表达过程中不被纠错打断。
23. 作为学习者，我希望反馈最多指出两个影响理解的问题，以便集中改善最需要调整的表达。
24. 作为表达清楚的学习者，我希望反馈如实说明表达清楚，并区分可选替代表达与错误，以便不因强制挑错而误解自己的表达。
25. 作为学习者，我希望反馈明确其仅依据确认文本，以便不把它误当成发音或综合能力评估。
26. 作为学习者，我希望反馈失败时得到明确说明和恢复动作，以便继续学习而不被记录成低能力或低分。
27. 作为学习者，我希望在同一练习中重新录制并提交新的作答，以便运用反馈，同时保留先前作答作对照。
28. 作为学习者，我希望离开后仍能找到未结束练习，并继续或删除，以便按自己的节奏学习。
29. 作为学习者，我希望至少一次作答获得当前有效反馈且没有处理中的请求时可主动结束，以便不因其他失败或未核对作答被迫重复完成全部步骤。
30. 作为学习者，我希望历史保留每次作答的真实状态，以便知道哪些已得到反馈、哪些仍失败或尚未核对。
31. 作为学习者，我希望已结束练习保持只读，以便回看稳定的学习记录。
32. 作为学习者，我希望从历史按原内容版本开启新的重练，以便对照相同任务下的表达变化。
33. 作为学习者，我希望从材料目录开始时使用最新可用版本，以便接触当前发布内容。
34. 作为学习者，我希望发布新版不会改变旧练习的材料、任务和反馈依据，以便正确理解历史。
35. 作为学习者，我希望原版本撤下后仍能查看历史，并得到不能按该版重练的说明，以便自行选择是否使用新版开始新练习。
36. 作为学习者，我希望删除整次练习及其作答、反馈，并如实获知文件清理情况，以便管理自己的学习记录。
37. 作为学习者，我希望处理超时或中断后能恢复到明确状态，以便不永久停留在“处理中”。
38. 作为维护者，我希望材料、音频、任务、释义和提示一起检查发布，以便学习者使用一致的内容版本。
39. 作为维护者，我希望开发替身清楚标识且不能在正式环境误启用，以便区分业务验证与真实服务体验。
40. 作为维护者，我希望通过公共业务接口和隔离数据库验证权限、版本与并发行为，以便调整内部实现时保留可靠的行为约束。
41. 作为中国大陆或海外的学习者，我希望实际部署下能完成录音、识别、反馈与重练，以便使用真正可用的学习流程。

## Implementation Decisions

本节均承接已确认架构及领域规则。模块名表示业务责任，不规定具体文件路径、函数签名或最终表字段。

### 应用与模块边界

- 保持一个 Next.js 应用，采用 Drizzle、Neon、Better Auth，以 Vercel 为首选部署平台。依赖在实施时锁定相容的稳定版本；先阅读实际安装版本的 Next.js 指南。初始按 Node.js runtime 设计，部署适配仍须验证。
- `identity` 负责可信身份、测试名单、账号访问资格、邮箱注册验证、登录、密码恢复、退出和会话撤销；认证数据由 Better Auth 管理。
- `learning-content` 负责可用材料、持久化内容版本、发布与撤下，以及供新练习和历史读取的版本选择。
- `practice` 集中负责学习记录所有权、作答、确认文本版本、反馈有效性、处理恢复、结束、历史、重练与删除。作答、转写、反馈、历史不分别拆成独立业务模块。
- 页面、Server Actions 和 Route Handlers 调用相同的模块公开接口。请求入口取得真实服务端身份；业务操作重新检查所有权、状态及版本。客户端自报身份和可操作状态不能作为授权依据。
- 跨模块只调用公开接口。表定义和查询归所属模块，迁移层汇总定义，依赖集中装配。外部语音、反馈、文件和邮件 Adapter 不直接写练习状态；数据库直接使用 Drizzle，不引入通用 Repository。
- 浏览器仅持有录音草稿、试听与播放位置、提示展开、未确认文字编辑等临时状态。刷新后从服务端记录恢复已接收作答和练习进度。

### 公开操作契约

| 操作 | 必须承担的业务责任与可观察结果 |
| --- | --- |
| 开始练习 | 选取材料最新可用版本，创建归属当前学习者的练习并固定内容版本 |
| 继续与读取 | 返回属于当前学习者的详情、历史、真实处理状态、允许动作及不可操作原因；继续不创建替代练习 |
| 从历史重练 | 检查原练习所有权和原版本可用性，创建新的练习；旧版撤下时拒绝且说明原因 |
| 提交作答 | 检查录音引用、所有权、练习状态和提交标识；返回已接收作答或明确失败／冲突 |
| 确认转写 | 在未结束练习中检查并发修改，保存确认文本版本；更正不增加作答次数 |
| 请求或重试反馈 | 固定原作答与确切确认文本版本，编排生成、校验、保存和失败恢复 |
| 重试识别 | 重新处理原作答，不创建新作答 |
| 结束练习 | 原子判断至少一份当前有效反馈且没有处理中的请求，成功后练习只读 |
| 删除练习 | 检查所有权，删除整次练习及作答、反馈，阻止迟到结果写回，按最终存储规则清理文件并报告结果 |

公开结果和错误采用业务含义，包括未授权、已结束、版本冲突、内容不可用和处理失败；具体错误编码与传输形态在实现时确定。页面负责中文呈现，不承担“先检查、再更新”的业务一致性编排。

### 内容与学习记录

- 内容源随项目维护。材料、音频、任务、释义和提示一起检查，发布为持久化内容版本；发布后的内容不可原地改写，撤下是独立的可用性变化。历史文字内容读取不依赖部署包是否仍含原源文件。
- 一次练习固定一个内容版本及其表达任务，拥有零至多次作答。材料目录开始使用最新可用版本；历史重练使用原版本。发布新版不自动撤下旧版，撤下旧版不删除历史，也不自动替换为新版。
- **P1：提交被接收才形成作答。** 聆听、查看帮助、试听和丢弃录音不增加作答次数；接收后即使识别失败也保留作答。未提交录音可能随离开丢失，界面明确提示。
- 原始转写与确认文本分别保存。确认文本用于还原实际口头表达；改善说法通过再次作答完成。
- **P2：更正创建新的确认文本版本。** 未结束练习可更正并重新确认，旧反馈保留且指向旧文本，新文本需重新请求反馈。已结束练习只读，可整次删除或重练。
- 反馈绑定确切确认文本版本，并保留生成规则版本及必要溯源信息。当前有效性由反馈依据和当前确认版本决定，不能用一个易失真的布尔标记取代该关系。
- **P3：至少一份当前有效反馈且无处理中的请求才可结束。** 不要求最后一次作答成功，不要求所有作答都已核对。若唯一反馈对应更正前的旧文本，则不再满足结束条件。
- 练习状态与识别、反馈等技术处理状态分别记录。结束不将失败或未核对的作答标成成功，不表示掌握表达。
- 文件使用稳定引用，临时签名访问地址不作为永久身份。历史音频可用性由待定的存储和保留规则约束，不能推导为永久保留所有录音。

### 反馈与语言

- 首次播放默认隐藏材料原文；随时可重听和查看原文、中文释义。表达帮助先提供关键词或句式，完整示例由学习者主动求助展开。
- 仅在录音后、确认文本后请求表达反馈。零至两个问题须聚焦影响理解之处；表达清楚时允许零个纠错项，可选替代表达不能自动标成原话错误。
- 反馈解释和建议使用中文；材料、英语引用、改进表达与学习者英语作答保持英文。操作、验证错误、空状态、恢复说明为中文，不提供界面语言切换。
- 反馈不包含发音、语调、停顿评价或综合分数。空输入、无可识别内容、供应商失败不能产生伪造反馈。
- `practice` 负责选择内容及文本版本、校验反馈并接受或拒绝结果。结构校验和质量样例检查都需要执行，合法结构本身不能证明反馈准确。

### 并发、幂等与恢复

- 提交标识稳定且限定在所属用户及练习范围内。相同标识与相同内容重发返回同一接收结果；相同标识携带不同内容返回冲突。提交结果不确定时，用同一标识查询或重发核对，不能直接新建作答。
- 再次作答使用新提交标识；重新识别和重新请求反馈仍属于原作答，不增加作答次数。
- 使用数据库约束与并发检查：短事务检查所有权、状态、版本并取得处理权；事务外调用 Adapter；短事务再次检查处理权、目标版本和记录存续状态后保存结果。具体锁或条件更新方案实施时验证。
- 结束与提交、发起处理共享并发控制。只有有效处理权可以接受结果；旧确认文本的迟到反馈不能成为新文本的当前有效反馈；已删除记录不能被迟到请求重新创建。
- 处理权有期限及明确恢复路径。超时或进程终止不能永久阻止结束；恢复后旧处理权不得写回。本地失效不代表远端已取消，远端结果未知须与明确失败区分。
- 数据库幂等不承诺供应商绝不重复收费。真实接入时验证远端幂等、超时和重复请求行为，落实可执行的恢复办法；不预先承诺任务队列或独立后台服务。
- 删除和文件清理部分失败时报告真实状态，不能显示“全部删除成功”。

## Testing Decisions

### 已确认的测试边界

主要业务测试通过调用方使用的模块公开接口进行，使用真实、隔离的 PostgreSQL 和可替换的外部 Adapter。`practice` 是学习流程一致性的主要测试入口；`identity` 和 `learning-content` 分别验证身份与内容契约。通过少量浏览器完整流程连接这三个模块，避免为内部转发层重复建测试边界。

这是已确认架构中的测试决定，本次不新增测试边界，也不重新请求确认。未查看现有业务或测试代码，因此不声称这些新接口已经存在。

好测试断言用户可观察结果、持久化后的可读状态、权限与恢复行为，不依赖内部调用次数、目录结构或 ORM 细节。并发与约束测试使用真实数据库；页面流程、模型反馈质量和真实服务可用性分别验证。纯规则可直接测试，但不为低价值转发函数建立镜像测试。

| A03 | 退出或撤销会话后，重放原会话不能继续受保护读写；不能只以浏览器 Cookie 已清除作为成功证据 | 3、5 |
| A04 | 用账号 A 读取、提交、确认、请求反馈、重试、结束、重练或删除账号 B 的记录均被拒绝，B 的记录未发生对应变更；请求伪造用户标识不能绕过检查 | 5、40 |
| C01 | 可选择已发布材料并播放；首次默认隐藏原文，可重听、展开原文和中文释义；先提供关键词／句式，主动求助后可见完整示例；任务要求表达自身情况 | 8–12 |
| C02 | 发布新版后，从目录开始引用新版，从原历史重练仍引用可用的原版；两个练习独立，旧任务、作答与反馈依据保持不变 | 32–34 |
| C03 | 撤下原版后仍可查看历史，按原版重练被拒绝并提示可另选新版；系统不自动替换版本；仅发布新版不会使原版自动不可重练 | 34、35 |
| C04 | 当前部署包移除旧内容源文件后，已持久化的历史材料文字、任务、释义与提示仍可读取；音频另按最终保留规则验证 | 34、38 |
| P01 | 只听、查看提示、试听、丢弃或重录草稿时正式作答数为零；主动提交被接收后为一，即使随后识别失败仍保留该作答 | 13–17 |
| P02 | 同一提交标识、相同内容多次或并发发送，只得到同一作答；响应丢失后查询／重发也不新增；同一标识换内容返回冲突 | 15、16、40 |
| P03 | 识别失败后重试仍处理原作答，反馈失败后重新请求仍指向原作答及指定确认版本；成功恢复不增加作答次数，失败保留明确原因和可执行动作 | 17、26、37 |
| P04 | 材料原文、原始转写与确认文本在展示和持久记录中含义清楚；未确认文本不能作为已确认依据直接得到有效反馈；纠正识别错误不计为新作答 | 18–21 |
| P05 | 确认文本从 V1 更正为 V2 后，V1 反馈保留并标明依据，不能显示为 V2 当前有效反馈；取得 V2 反馈后才恢复该作答的当前有效性 | 20、21 |
| P06 | 基于 V1 的反馈在 V2 确认后迟到，不能覆盖 V2 的反馈或满足 V2 的结束资格；如保存，只能作为 V1 历史反馈 | 21、40 |
| P07 | 根据建议重新录制并以新标识成功提交，产生同一练习的第二次作答；第一次的文本与反馈完整保留 | 27 |
| P08 | 刷新或关闭页面不自动结束练习；再次进入可继续同一未结束练习或删除，已接收作答可恢复；离开前明确告知未提交录音可能丢失 | 14、28 |
| P09 | 没有当前有效反馈或仍有处理中的请求时不能结束；至少一次作答有当前有效反馈且无处理中请求时可以结束，其他失败或未核对作答保留真实状态 | 29、30 |
| P10 | 唯一反馈因确认文本更正而成为历史反馈时不能结束；另一次作答仍有当前有效反馈且无处理中请求时可以结束；零纠错项的成功反馈也满足有效性条件 | 21、24、29 |
| P11 | 结束与提交／发起处理并发执行后，不出现“已结束且又接收新作答／新处理”的非法结果；已结束后更正、追加作答与新处理均被拒绝 | 29、31、40 |
| P12 | 从历史重练创建新的练习，不向原练习追加作答；结束后的原记录保持只读，仍允许按规则整次删除或重练 | 31、32 |
| P13 | 模拟超时或进程中断后，经实际恢复路径转为明确状态，不永久显示处理中；失效处理权的迟到结果被拒绝；远端结果未知时不谎称已取消或确定失败 | 37、40 |
| P14 | 并发重试只产生一份有效处理权对应的可接受结果，旧处理不能覆盖新结果；检查持久化结果与可读状态，不以内部函数调用次数作为断言 | 16、37、40 |
| P15 | 删除整次练习后无法继续读取其作答和反馈，进行中的迟到请求不能复活记录；文件清理失败按最终规则明确呈现，不谎报全部成功 | 36、40 |
| F01 | 确认文本后才请求反馈；中文说明配英文引用／改进表达，问题数为零至二；清楚表达样例允许无纠错项，风格替代不冒充错误 | 22–24 |
| F02 | 实际反馈样例不评价发音、语调或停顿，不给综合分数；界面清楚标注文本依据，结束记录不显示“已掌握”结论 | 25、29 |
| F03 | 空文本、无可识别内容、非法供应商响应和供应商失败不产生有效反馈；失败提示可理解、可操作，不能展示固定假反馈冒充真实结果 | 26、39 |
| U01 | 手机与电脑浏览器主要流程、空状态、验证与失败提示均为中文；学习材料、示例与英语作答保持英文；没有界面语言切换入口 | 7 |
| U02 | 实际手机与电脑设备分别完成麦克风授权、录音、试听、提交、真实识别、核对、反馈、再次作答及重练；权限拒绝或采集失败时有可理解的恢复提示 | 7、13、27、41 |
| R01 | 开发／测试替身明确标识且仅在对应环境启用，正式环境不能误启用；替身测试结果与真实服务结果分别报告 | 39 |
| R02 | 中国大陆与海外分别验证实际部署访问及完整语音学习链路；记录设备、浏览器版本、地区、服务配置与结果，不能用模拟移动视口或本地成功替代 | 41 |
| R03 | 最终文件方案下，私有录音的访问、历史回放、保留及删除符合已补充规则；未授权账号不能访问私有录音；未定规则前此项保持未验收 | 5、36、41 |
| R04 | 首批六类主题的文本、音频、任务、释义与提示完成一致性检查；实际试用能够走完表达自身情况及再次尝试流程，记录难度调整，不把完成次数当能力提升证据 | 8、11、38 |

A02 的异常令牌用例、U02 的录音失败提示是对已确认认证／录音流程的验收细化；具体令牌有效期、录音时长、大小和格式限制仍须在实施及真实接入时确定，不由这些场景暗中定值。

| 1 新骨架、数据与身份 | 三个模块基础、中文页面骨架、认证与新数据模型 | 实施前工作区快照可恢复且包含未提交改动；稳定依赖可复现安装；配置检查、类型检查、lint、生产构建通过；在独立空测试库执行迁移成功；A01–A04 对已交付身份及记录入口通过，邮件替身与真实投递分开报告 |

首版可用要求四阶段适用门槛均完成。构建成功、生成迁移 SQL、替身流程成功、结构化反馈合法，各自只能证明对应范围；不能替代真实迁移、真实语音、真实邮件或跨地区部署验收。

每次验收记录环境、场景编号、实际结果、证据与未执行原因。类型、构建、数据库测试、浏览器操作、真实服务分别报告；未执行不记通过。独立测试数据库未就绪时报告阻塞，不把现有配置中的数据库当作可清空测试库。

### 既有测试依据及适用范围

现有 QA 文档描述了通过真实 HTTP／Server Actions、会话和数据库验证行为，在外部调用处替换供应商，以及分别报告浏览器与真实服务验收的做法。复用这些测试思想，不承诺复用未经检查的旧脚本或旧接口。

2026-10-02 的冻结报告可为新断言提供历史反例：B01 对应跨账号写入检查，B02 对应撤销会话后的重放拒绝，B04 对应历史任务依据稳定，B05 对应重复请求的副作用控制，B08 对应受保护入口的鉴权。历史中的写作、发音评分及账号删除功能不因此进入首版范围。旧报告的构建、通过数量及缺陷状态也不代表当前实现状态。

## Out of Scope

首版不包含以下能力，也不因旧版本曾出现而自动重建：

- 写作模块、独立 AI Coach、自由口语或角色往返对话；以复述材料为主的首个输出流程。
- 发音、语调、停顿评分、综合分数、语法完全正确门槛或“已掌握”判定。
- 自动复习日程、连续打卡、积分、课程等级体系和通用练习插件平台。
- 用户导入材料、按话题即时生成材料、内容管理后台或任意任务编排。
- 双语界面、语言偏好、第三方登录、原生 App、支付订阅。
- 公开注册；何时开放另待流程、服务与费用验证后决定。
- 旧学习数据迁移、旧模型兼容、全量旧功能复现或销毁现有远端数据库及文件。
- 预先拆分独立后端、多应用、常驻 WebSocket 或任务队列；如部署实测提出必要性，再形成相应决定。

以下属于**延后决定但首版接入／上线前必须落实**，不能与排除范围混为一谈：

| 待决事项 | 处理时点 | 未决时的限制 |
| --- | --- | --- |
| 语音识别、反馈生成、材料音频制作与邮件供应商 | 第三阶段真实接入前集中比较决定 | 可验证替身下业务；不能验收真实识别、反馈质量、材料听辨和邮件投递 |
| 文件存储及录音保留期限、访问和清理规则 | 文件真实接入前，与服务费用一同决定 | 私有文件访问、历史音频可用性、删除完成语义未能最终验收；不能宣布退出 Supabase 已完成 |
| 预算、费用上限、外部重复请求成本处理 | 按真实服务报价及能力，在接入前决定 | 不虚构月度预算，不承诺远端绝不重复收费 |
| 实际部署地区及大陆／海外可用性 | 第三阶段按真实链路验证决定 | Vercel 仍为首选，不能先假设两类地区都可用 |
| 恢复触发方式、可靠执行路径、远端结果未知的处理 | 第二阶段验证业务约束，第三阶段结合平台和供应商落实 | 不能只登记任务而没有可执行恢复路径，不能让处理中状态永久阻止结束 |
| 录音时长、大小、格式，浏览器版本矩阵及是否需要媒体转换 | 实施与真实接入验证时确定 | 不继承旧媒体链路为必选方案，不宣称所有设备／格式兼容 |
| 首批材料数量、检查及制作方式、实际难度 | 首份材料阶段起落实，第四阶段扩充与试用校准 | 不预设用户等级，也不虚构逐主题数量 |
| 首条流程交付日期及后续开放时间 | 当前未提供；需要排期时另定 | 不在本规格承诺日期，也不作为开始第一阶段的前置条件 |
